OVERVIEW
================================================================================

A new specialized REST API endpoint has been created for creating trading
strategies optimized for market depth analysis. This endpoint simplifies the
process of creating depth-based trading strategies by providing a dedicated
interface with built-in validation and sensible defaults.

================================================================================
NEW ENDPOINT
================================================================================

POST /api/v1/strategies/depth-market/create

Base URL: http://localhost:8080/api/v1/strategies/depth-market/create

This endpoint creates a new depth market trading strategy with comprehensive
support for:
- Market depth analysis parameters
- Liquidity filters
- Price and volume constraints
- Risk management controls
- Trade execution configuration

KEY FEATURES
================================================================================

1. SIMPLIFIED INTERFACE
   - Dedicated endpoint for depth market strategies
   - Cleaner request body structure
   - Automatic depth_only flag in conditions
   - Sensible parameter defaults

2. DEPTH MARKET PARAMETERS
   - min_bid_quantity: Minimum bid depth volume
   - min_ask_quantity: Minimum ask depth volume
   - max_spread_pct: Maximum bid-ask spread percentage
   - require_ltp_between_spread: LTP validation
   - depth_only: Automatically set to true

3. MARKET QUALITY FILTERS
   - volume_threshold: Minimum daily trading volume
   - price_range_min/max: Stock price range filtering
   - min_market_cap/max_market_cap: Market cap filtering
   - Ensures only quality stocks are selected

4. COMPREHENSIVE RISK MANAGEMENT
   - max_daily_trades: Daily trade limit
   - max_loss_per_day: Daily loss limit
   - position_sizing: FIXED or PERCENTAGE
   - max_portfolio_exposure_pct: Portfolio exposure limit
   - max_per_trade_risk: Per-trade risk cap
   - enable_risk_checks: Risk validation toggle
   - enable_auto_square_off: Market close auto-exit
   - auto_square_off_time: Configurable exit time

5. FLEXIBLE STOP LOSS
   - stop_loss_type: FIXED or TRAILING
   - stop_loss_pct: Fixed stop loss percentage
   - trailing_sl_pct: Trailing stop loss percentage
   - take_profit_pct: Take profit percentage

6. COMPLETE TRADE CONFIGURATION
   - order_type: LIMIT or MARKET
   - order_side: BUY or SELL
   - quantity: Trade quantity
   - limit_price: For limit orders
   - validity: DAY, GTC, IOC
   - product_type: INTRADAY, DELIVERY, CASH

7. AUTHENTICATION SUPPORT
   - Bearer token (JWT)
   - App ID (client identification)
   - Source platform tracking
   - Can be provided via headers or request body

================================================================================
VALIDATION RULES
================================================================================

Required Fields Validation:
- user_id: Must not be empty
- strategy_name: Must not be empty
- stock_codes: Array with minimum 1 element
- exchanges: Array with minimum 1 element
- order_type: Must be LIMIT or MARKET
- order_side: Must be BUY or SELL
- quantity: Must be integer > 0
- exchange: Must not be empty
- position_sizing: Must be FIXED or PERCENTAGE

Conditional Validations:
- If order_type = LIMIT: limit_price should be provided
- If stop_loss_type = TRAILING: trailing_sl_pct should be provided
- If max_daily_trades specified: Must be > 0
- If max_loss_per_day specified: Must be > 0

Range Validations:
- stop_loss_pct: Typically 0.5-10%
- take_profit_pct: Typically 1-20%, should be > stop_loss_pct
- max_spread_pct: Typically 0.1-2%
- volume_threshold: > 0 if specified
- price_range_min < price_range_max (if both specified)
- min_market_cap < max_market_cap (if both specified)

================================================================================
HTTP STATUS CODES
================================================================================

201 Created
- Strategy successfully created
- Returns full strategy object

400 Bad Request
- Missing or invalid required fields
- Includes error message describing the issue

401 Unauthorized
- Invalid authentication credentials
- Check Authorization, appId, source headers

500 Internal Server Error
- Server-side error during creation
- Check backend logs

503 Service Unavailable
- Backend service not reachable
- Verify service is running

BEST PRACTICES
================================================================================

1. START CONSERVATIVE
   - Set lower trade quantities initially
   - Use smaller max_daily_trades
   - Set reasonable stop loss percentages

2. RISK MANAGEMENT FIRST
   - Always set max_daily_trades
   - Always set max_loss_per_day
   - Enable risk_checks in production

3. VALIDATION BEFORE CREATION
   - Validate all fields locally
   - Check stock codes exist
   - Verify market hours

4. TEST THOROUGHLY
   - Use test script before production
   - Monitor strategy after creation
   - Review execution quality

5. AUTHENTICATION SECURITY
   - Keep bearer tokens secure
   - Rotate tokens regularly
   - Use HTTPS in production

6. PARAMETER TUNING
   - Monitor fill rates
   - Adjust max_spread_pct based on results
   - Review and optimize after each trading day
